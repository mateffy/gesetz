gesetz.

gesetz is a quality-assurance gate that lets you write your own code-quality and architecture rules in plain TypeScript — and runs them alongside ESLint, PHPStan, and Vitest in a single scored report. One command, one score, one decision.

## what it does

Every codebase has conventions that no generic linter knows about. "No file over 400 lines." "Every module needs a test next to it." "Feature A must not import internals from Feature B." ESLint, PHPStan, and Vitest are excellent at what they do, but they don't know your architecture. gesetz bridges that gap: you write project-specific rules in TypeScript, and gesetz runs them alongside your existing tools in one unified Violation format, one category score, one CLI.

gesetz does not replace your linters. It wraps them. You still run ESLint and Vitest — but their output and your custom rules all feed into the same report. Because the rule engine is polyglot, the same gesetz check covers your TypeScript frontend, your PHP backend, and whatever else lives in the repo.

## the categories

Every rule belongs to a category, and every category gets a score from 0 to 10. A project passes when every category that has rules meets its configured threshold (default 7). Categories are extensible — category is just a string, so you can define your own.

weighted = errors·1.0 + warnings·0.5 + infos·0.1 → score = max(0, 10 − weighted)

strictness

Type discipline: any, double casts, missing return types, enums, default exports.

structure

Code shape: file/function size, nesting, magic numbers, empty catch blocks.

organization

Monorepo health: cycles, layer violations, import discipline, file pairing.

cleanup

Dead code and AI residue: console logs, trivial comments, debugging files.

security

Secrets, SQL injection, unsafe innerHTML, hardcoded tokens.

## commands

check

Runs every rule and prints the category scores, violations, and pass/fail verdict.

list

Lists every rule with its category and agent-facing guidance.

init

Creates a gesetz.config.ts — interactive wizard or auto-detecting in CI/agent mode.

skill

Prints a markdown agent skill file you can pipe into your agent's skill directory.

## the whole surface

--format json|ci

Compact JSON envelope for agents; GitHub Actions ::error annotations for CI.

--since main

Only report violations in files changed since a git ref.

--category strictness

Run only one category (comma-separated for several).

--threshold 8

Override every category threshold from the CLI.

--watch

Re-run incrementally on every file change, backed by a content-hash cache.

gesetz auto-detects its format: in a TTY you get the lush table; when stdout is piped or an agent env var is present, it switches to a compact JSON envelope. Exit code is non-zero on failure, so it drops straight into CI.

## the check catalog

gesetz ships a catalog of ready-made checks, grouped by what they need to run — the thing you have to know when composing a config.

## A · universal — any file, no backend

Text/regex and file-system checks that work on any language. No parser required.

requireSibling('.test.ts')

Every Foo.tsx must have a Foo.test.ts.

requireChildren(['README.md'])

Each matched directory must contain required files.

noGodFile({ maxLines: 400 })

Flags files over the threshold.

noDebugLogging()

Polyglot: console.* in TS, dd() in PHP, print in Python — one rule.

noHardcodedSecret()

Heuristic for api_key = "…", token: "…", passwords.

## B · syntax-tree — needs a backend

Structural checks that require a SyntaxBackend. If none matches, the check silently returns no violations.

noDirectCalls(['eval', 'fetch'])

Ban specific function calls by name (member access supported).

requireNamingConvention(...)

Functions, classes, methods must match a regex.

requireDocstrings({ kinds: ['class'] })

Structural items must have a docstring.

requireRelatedExports(getRelated)

Every useX exports useSuspenseX and useCachedX.

## C · architecture & imports

Import discipline and monorepo layering. Accurate with a backend; falls back to JS/TS regex.

noImportFrom('src/legacy')

Ban imports from a module, with a custom fix message.

defineArchitecture(config)

Declare layers as globs and enforce import constraints — one batched rule.

noCycles('src/**/*.{ts,tsx}')

Detect circular dependencies via import extraction + DFS.

## D · TypeScript/JS — @gesetz/typescript

Register typescriptSyntaxBackend (oxc-parser + ast-grep) to enable noConsoleLog, noEmptyCatch, noTypedAny, noDefaultExport, noFunctionCalls, requireOptionsObject, plus JSX/i18n checks and test quality via requireMinTestScore.

## E · PHP, Laravel, Effect-TS

@gesetz/php ships phpSyntaxBackend and checks like strictTypes, psrNamespace, noRawDbQueries. @gesetz/laravel bundles opinionated presets. @gesetz/effect-ts catches the anti-patterns AI agents most often introduce.

## tool adapters

Tool adapters wrap the linters and test runners you already use and normalize their output into the same Violation[] shape.

@gesetz/eslint

Runs ESLint programmatically. Use for type-checked rules like no-floating-promises.

@gesetz/oxlint

Fast Rust linter — use with --type-aware for typed rules.

@gesetz/vitest

Runs tests with a JSON reporter and maps failures to violations.

@gesetz/phpstan

Runs analyse --error-format=json.

@gesetz/prettier · oxfmt

Format checks via --list-different.

@gesetz/phpunit · pest · bun-test · storybook

JUnit XML bridges that map test failures to violations.

## write your own rules

A rule is a glob plus a check. Enforce any convention your team agrees on: 

// rules/quality.ts — no god files, no hardcoded secrets
import { select, noGodFile, noHardcodedSecret, noDebugLogging } from 'gesetz';

export const noGiantFiles = select('src/**/*.{ts,tsx,php,py}')
  .label('Files should not exceed 400 lines')
  .check(noGodFile({ maxLines: 400 }));

export const noSecrets = select('src/**/*')
  .label('No hardcoded secrets')
  .check(noHardcodedSecret());

// noDebugLogging is extension-aware: console.* in TS, dd() in PHP,
// print in Python, fmt.Println in Go, println! in Rust — one rule.
export const noDebug = select('src/**/*')
  .label('No debug logging left in code')
  .check(noDebugLogging());

## the select builder

Most rules are built by chaining select(). The glob picks files, .check() applies checks to every match, .label() gives a human description (auto-slugified to the rule id), .category() sets the score bucket, and .guidance() feeds agent-facing docs. 

export const everyComponentNeedsStory = select('src/**/*.tsx')
  .exclude('**/*.test.tsx')
  .label('Every component needs a Storybook story')
  .category('organization')
  .guidance({
    what: 'Components without a story are invisible to design-system consumers.',
    do: 'Create a Foo.stories.tsx next to every component.',
    dont: 'Skip stories for "simple" components — they all evolve.',
  })
  .check(requireSibling('.stories.tsx'));

## get started

1. install

bun add -d gesetz @gesetz/typescript @gesetz/vitest @gesetz/eslint

2. initialize

gesetz init

Creates a gesetz.config.ts. In a TTY it runs an interactive wizard; in CI or agent mode it auto-detects your framework and installed tools.

3. run the gate

gesetz check

Repeat runs are near-instant: violations are cached as markers in .gesetz/cache.db and files are fingerprinted by content hash, so only the files you edited get re-checked. --full bypasses the cache; --watch re-runs incrementally.

4. make it agent-native

gesetz check --format=json --since HEAD   # one JSON envelope
gesetz skill > .agents/skills/gesetz/SKILL.md   # teach your agent the gate
